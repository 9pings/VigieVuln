## Safe integration criteria

Any future direct GHSA ingestion should be evaluated against measurable OSV synchronization gaps before activation. Keep the provider, exact IDs, versioned snapshot commit, fetched time, original data, explicit aliases and review status. Parse affected ranges per ecosystem conservatively, including GitHub's `last_known_affected_version_range` extension; return unknown for unsupported or ambiguous bounds. Reconcile OSV and GitHub records only through declared IDs, retaining both source provenances and conflict warnings. A complete verified snapshot or explicit withdrawal can update a record's state; incomplete pages, errors and an absent item must never be interpreted as clean or deleted. Preserve withdrawals and expose stale or incomplete coverage in offline results. The proxy and seed should distribute the same versioned records and attribution, support offline matching, and use atomic updates. Test pagination, withdrawn advisories, update ordering, archive truncation, conflicts, and cold/warm offline equivalence before release.

GitHub's [global advisory API](https://docs.github.com/en/rest/security-advisories/global-advisories) exposes review type, updated time, package ranges and `withdrawn_at`; available data must be evaluated individually rather than assuming that every global record has usable package metadata. The separate per-repository API cannot be converted into a complete global source merely by querying the repositories found in one benchmark. Such a design would miss other publishers, depend on GitHub API access/rate limits, and require a separate rights and freshness assessment before seed redistribution.
