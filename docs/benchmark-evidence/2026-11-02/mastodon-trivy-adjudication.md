# Mastodon: individual adjudication of 22 Trivy-only Ruby records

Reviewed on 2 November 2026 for Mastodon commit `fbcbf7898f000d9d1a21d52e8a8d3ed4602aa7db`, using the OSV-only VV run (158 findings) and Trivy comparison described in [BENCHMARK.md](../../BENCHMARK.md).

**Result: 18 confirmed missing advisory records, 1 false alert for the selected version, 1 already reported alias, 2 indeterminate cases.** These categories concern package/advisory observations. A confirmed source-coverage gap does not establish an exploitable Mastodon instance, a distinct underlying incident, or a bug in VV's matching code. In particular, development dependencies are included in this lockfile comparison.

Each of the 22 maintainer advisories was fetched directly from the owning repository's public GitHub advisory API (HTTP 200, none withdrawn). The OSV ID lookup was repeated: 21 GHSA IDs returned 404; the CVE returned 200. A 404 is only evidence for that ID lookup, not proof of absence under every possible alias/provider. The existing VV output was checked per package/version and explicit primary ID. We do not infer aliases from shared references, titles, or previous incomplete fixes. The [machine-readable review](mastodon-trivy-adjudication.json) records source URLs, SHA-256 hashes, ranges, scan identity and observations. No RubySec advisory descriptions or native corpus are copied into this evidence.

The runtime declaration is [`.ruby-version` at the project commit](https://github.com/mastodon/mastodon/blob/fbcbf7898f000d9d1a21d52e8a8d3ed4602aa7db/.ruby-version) (`3.0.3`). [The same commit's Gemfile](https://github.com/mastodon/mastodon/blob/fbcbf7898f000d9d1a21d52e8a8d3ed4602aa7db/Gemfile) declares `idn-ruby`, required as `idn`. [Addressable 2.8.0's loader](https://github.com/sporkmonger/addressable/blob/addressable-2.8.0/lib/addressable/idna.rb) selects native IDNA when available and otherwise falls back to pure Ruby. A manifest declaration is not a measurement of the loaded backend; GHSA-9crm-g4mf-wc5j therefore remains indeterminate for this project.

For Nokogiri, the exact 1.13.6 source uses the older `duplicate_node` implementation and does not expose the required method. The method was [introduced in January 2024](https://github.com/sparklemotion/nokogiri/commit/1e7d38affc10917f12372fab97a505e6dbb8368b); the [June 2026 fix](https://github.com/sparklemotion/nokogiri/commit/630f07344149e596de1d04c9d7a80533abc055f7) adds its argument type check. This contradicts the advisory's overly broad `<1.19.4` interval for 1.13.6. The verdict is limited to this named issue and version, and does not assert that Nokogiri 1.13.6 is otherwise safe.

The six net-ssh mechanisms were reviewed statically in the exact v6.1.0 sources (commit `74919ef69344164bd55e2dfc7ee2a360b6c718c6`), rather than extrapolated solely from tests on later versions. No attack was run against a deployment, no resource exhaustion was attempted, and actual dependency reachability was not measured. The source evidence establishes the affected mechanism, not the downstream application's exposure.

No product rule, suppression or new provider is introduced by this adjudication. RubySec redistribution remains disabled; this review uses original summaries and direct maintainer/source evidence.
