# Dubbo Snyk comparison — 2 November 2026

This is an evidence inventory, not a final verdict on the validity of Snyk's findings. Snyk CLI 1.1302.1 scanned 98 projects in the pinned Dubbo checkout. It returned exit code 1 and valid JSON with 4,395 vulnerability occurrences. The raw report contains organization data and is intentionally not published. The comparison uses the 1.2.0 development-tree VigieVuln online report used in the benchmark; it is not a claim about a published release.

Within each scanner the comparison groups repeated Snyk records by exact Maven coordinate, version and Snyk ID; VigieVuln findings are keyed by their own ID. Reactor coordinates `org.apache.dubbo:*` are excluded in both. A cross-scanner match requires the exact coordinate and version and an explicitly declared common advisory ID; CWE identifiers and shared links are not aliases. On that basis there are 708 unique Snyk records, 541 matching at least one VigieVuln record, 167 without a match and 184 VigieVuln records without a Snyk match. These figures are not comparable as recall percentages: scanner inventories, source coverage, advisory groupings and resolutions differ. Some records may refer to the same issue without a formally declared shared ID.

[Individual evidence](dubbo-snyk-adjudication.json) records all 167 unmatched Snyk records, their package, version, Snyk ranges, references, explicit identifiers, OSV HTTP statuses and version evidence. [Batch query](dubbo-snyk-osv-batch-request.json) and [response](dubbo-snyk-osv-batch-response.json) cover the 57 distinct package/version pairs. The live OSV query was supplemented with a reverse-identifier lookup over the official [OSV Maven archive](https://osv-vulnerabilities.storage.googleapis.com/Maven/all.zip), downloaded 2 November 2026, SHA-256 `d00b30a26258708c2a2541b785df45826d8a47ff4307a69717066f8055c770b0`: 7,224 JSON records parsed with no malformed entries. Only explicitly declared IDs and aliases were indexed. The archive may change. The scripts in `scripts/` document the analysis and use local `/tmp` paths; reproduction needs the original inputs and the stated snapshots. The comparison script produces a private intermediate and must not be published without review.

The categories in the JSON describe **OSV evidence only**:

- **38: same Maven coordinate in the OSV archive, but the tested version was not returned by the live package/version query.** This establishes a difference in source metadata, not that either source is correct.
- **58: the declared identity was found in OSV Maven records for other coordinates only.** The exact affected artifact needs independent verification; related Maven artifacts can carry or depend on one another.
- **71: no declared identity found in that Maven archive.** Other ecosystems and sources may have the advisory. This is indeterminate, not evidence that the Snyk finding is wrong or missing from every public source.

A separate CVE ID lookup returned HTTP 200 on 126 cases and HTTP 404 on 17; 24 have no CVE declared by Snyk. The 17 404 responses were rechecked: 13 explicitly listed aliases, and all 13 alias records returned HTTP 200 (eight Bitnami and five GitHub records); the remaining four said only `Vulnerability not found`. The body and resolved records are retained in the individual evidence. An OSV direct-ID 404 is not evidence of absence from OSV or from other sources.

Independent spot checks illustrate why final adjudication remains open. [GHSA-gm62-rw4g-vrc4](https://github.com/advisories/GHSA-gm62-rw4g-vrc4) explicitly links CVE-2023-6481 to `logback-core` versions 1.2.12, 1.3.13 and 1.4.13; Snyk flags 1.2.2, so the sources disagree on the tested version. For `logback-classic`, [GHSA-p47f-322f-whfh](https://github.com/advisories/GHSA-p47f-322f-whfh) identifies `logback-core` for CVE-2026-9828; that does not independently establish whether the reported classic artifact is affected. For the `grpc-core` finding with a Snyk-only ID, the upstream [gRPC issue](https://github.com/grpc/grpc-java/issues/7105) exists, but establishing applicability to 1.12.0 requires further source and version analysis. These examples do not classify the remaining records by analogy.
