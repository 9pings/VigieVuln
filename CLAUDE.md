# CLAUDE.md

Code-level orientation for contributors and Claude Code sessions on this repo.

## What this is

`fad-checker` — **Fucking Autonomous Dependency Checker**. Node.js CLI (`fad-checker`, or short alias `fad`) that:

1. Walks a multi-module Maven tree, removes private/excluded dependencies (regex on groupId), writes a parallel directory of "cleaned" POMs that can be fed to Snyk — and **mirrors every non-Maven lockfile/manifest** (npm/yarn/pnpm, composer, pypi, nuget, go, ruby) into that same tree (`lib/manifest-copy.js`) so `snyk test --all-projects` on the cleaned tree scans every ecosystem, not just Maven.
2. Walks every JS package (`package.json` + `package-lock.json` v1/v2/v3, `yarn.lock` v1 **or Berry/v2+**, or `pnpm-lock.yaml` v5/v6/v9), every PHP package (`composer.lock`, or `composer.json` best-effort), and every Python project (`poetry.lock`/`Pipfile.lock`/`uv.lock`/`pdm.lock`, or `pyproject.toml`/`requirements*.txt` best-effort — the whole requirements family, incl. `requirements-pinned.txt`), and every .NET project (`packages.lock.json`, or `*.csproj`/`*.fsproj`/`*.vbproj`+`Directory.Packages.props`/`packages.config` best-effort), every Go module (`go.mod`/`go.sum`) and every Ruby app (`Gemfile.lock`) in the same source tree. Each ecosystem is a **codec** (`lib/codecs/`): maven, gradle, npm, yarn, composer, pypi, nuget, go, ruby, binary. Adding one is adding a codec. The **Gradle codec** reads `gradle.lockfile` (authoritative, resolved + transitive), `gradle/libs.versions.toml` version catalogs, and best-effort `build.gradle`/`build.gradle.kts` (Groovy **and** Kotlin DSL — string/map notation, `libs.*` catalog accessors, `$var`/`gradle.properties`, incl. `buildSrc/` convention plugins); since a Gradle dependency *is* a Maven coordinate it emits `ecosystem:"maven"` records (bare `g:a` key → the Maven CVE-index, OSV `Maven`, transitive resolution, outdated and EOL all cover it unchanged) tagged `ecosystemType:"gradle"` so the report gives it a dedicated **Gradle chapter** + a `constraints { }` fix recipe, and surfaces `platform(...)`/`enforcedPlatform(...)` BOMs into the same `lib/maven-bom.js` import-BOM backfill the Maven path uses (so `spring-boot-dependencies` → the versionless `spring-boot-starter-*` get their versions). `--no-gradle` disables it. The Maven codec additionally scans **embedded binaries** — committed `.jar`/`.war`/`.ear` archives (vendored libs, Spring-Boot fat-jars, shaded uber-jars) are unzipped in-memory (via `fflate`, recursing into nested jars without touching disk) and their Maven coordinates read from `META-INF/maven/.../pom.properties` → `MANIFEST.MF` → file name. These get `provenance: "embedded"` and are listed in their own **report chapter 2.1** — a full inventory of *every* embedded coordinate (vulnerable or not, the JAR twin of chapters 2.2/2.3), with CVE status cross-referenced per coord and the full CVE detail for vulnerable ones (`--no-jars` to disable; built by `lib/embedded.js#buildEmbeddedInventory`, shared by the HTML report + JSON export). The **binary codec** finds committed **native binaries** — `.dll`/`.exe`/`.so`/`.dylib` that no package manager governs — selected by extension **and** magic-byte confirmation (PE/ELF/Mach-O; images/fonts/assets are rejected even with a spoofed extension), hashed (SHA-1 + SHA-256, `provenance: "binary"`), then **identified by checksum** online (deps.dev query-by-hash → exact package coordinate; CIRCL hashlookup → known OS/distro/CDN/NSRL file + free `KnownMalicious` flag) to answer two questions: is it **unmodified/known** (integrity), and does it **exist in a registry and therefore belong as a declared dependency** (governance). Surfaced in report **chapter 2.2 (Unmanaged / vendored binaries)** (`--no-binaries` to disable). No malware/antivirus lane and no binary-metadata parsing — identity is hash-lookup, integrity is hash-comparison. Finally, a standalone **certificate / key-material scanner** (`lib/certs/`, NOT a codec — crypto material has no version/registry/CVE/EOL) walks the tree for committed **X.509 certificates** (`.pem`/`.crt`/`.cer`/`.der`, parsed with Node's built-in `crypto.X509Certificate` → `expired` / `expiring` (`--cert-expiry-days`, default 90) / `weak-key` RSA<2048 / `weak-signature` MD5/SHA1 via OID byte-scan / `self-signed`), **private & public keys** — each labelled **private** (committed secret → critical) or **public** (low) — across PEM (PKCS#1/8/SEC1), **OpenSSH of every algorithm** (RSA/DSA/ECDSA/Ed25519 incl. FIDO `-sk`), PuTTY `.ppk`, PGP and one-line SSH (`*.pub`/`authorized_keys`/`known_hosts`), and **keystores** (JKS/JCEKS by magic, PKCS#12 by extension — contents not decrypted, hashed). Surfaced in report **chapter 2.4 (Certificates & key material)** + JSON `certificates` + SARIF `FAD-*` rules; **100% offline** (no network, no decryption), inventory-only (not wired into the `--fail-on` gate). `--no-certs` to disable.
3. Scans the union against:
   - the CVEProject `cvelistV5` Maven-relevant index (built locally),
   - OSV.dev (multi-ecosystem),
   - the Packagist security-advisories API (Composer — the database `composer audit` itself
     queries; `lib/packagist-audit.js`. Closes the measured recall class where OSV carries a
     CVE only as a CVEProject entry without composer coordinates — twig/twig CVE-2026-46636/
     46627, knplabs/knp-snappy CVE-2026-46643 on the real-instance corpus. Only package
     NAMES travel, like the registry pass; `-d packagist-audit` disables),
   - NIST NVD (enrichment: CVSS, CPE configurations, references),
   - EPSS (FIRST.org exploit-prediction percentile) + CISA KEV (known-exploited catalogue) — prioritisation signals,
   - European references (`lib/eu-refs.js`): ENISA EUVD id + exploited flag (`lib/euvd.js`, bulk mapping dump + exploited catalogue — REPORTED, never moves the priority band or the `kev` gate), GCVE id (`lib/gcve.js`, computed: CVE-Y-N = GCVE-0-Y-N, no request) and the CERT-FR advisories citing the CVE (`lib/certfr.js`, local incremental CVE → advisory index, entry-map cache so `--import-cache` merges it). No CVE id of the project is sent. `-d euvd,certfr`,
   - retire.js (vendored JS signatures),
   - optionally Snyk (`--snyk`).
4. Cross-checks every match's NVD CPE configurations against the dep version (`lib/cpe.js`) to filter false positives, then computes a **composite priority** per match (`lib/priority.js`): KEV (exploited) > EPSS-weighted CVSS, exposed as a band + score and used to sort the report.
5. Reports EOL frameworks (endoflife.date — Maven & npm), obsolete libs (curated Maven + npm-registry per-version `deprecated` field — authoritative, skips nothing), outdated libs (Maven Central + npm registry `dist-tags.latest`), and **licenses** (`lib/license-policy.js`, **opt-in — off by default, enable with `--licenses`**): each dep's license is normalised to SPDX and classified (permissive / weak / strong / network copyleft / proprietary / unknown), with copyleft & unknown flagged. **WebJars** (`org.webjars*`) are reduced to their npm coordinate by `webjarToNpm()` and run through the npm EOL/deprecation/outdated paths — so e.g. `org.webjars:angularjs:1.8.3` is flagged EOL. Each EOL finding is **traceable to its origin**: the report's EOL chapter shows a **Source** column (`endoflife.date/<slug>` + the `data/eol-mapping.json` rule that matched — `via`/`viaKey`, one of group-artifact/group-prefix/npm-name/npm-scope/webjar/composer-name/pypi-name/nuget-name), and for a **transitive** ("dep of a dep") EOL finding the Dependency column renders the resolver's `via` chain (`root → … → dep`) instead of a defining manifest. The chapter is **split into two sub-sections**: **Direct dependencies** (declared in a manifest or inherited from a parent POM — `dep.scope !== "transitive"`, the actionable ones) then **Transitive dependencies** (bump the direct dep that pulls them in). EOL has **two lifecycle levels**, read from endoflife.date's two fields (whose booleans have OPPOSITE polarity — `eol:true` = *is* EOL, `support:true` = *still* supported): `eol` (no fixes at all, always reported) and `unsupported` (bug-fix support ended, security fixes still provided — **opt-in via `--eol-support`**, rendered as its own "Out of active support" band with the same 6-column table so the `.doc` converter is untouched). **Composer frameworks are grouped**: the packages versioned in lockstep with Symfony/Laravel are listed in `data/eol-composer-frameworks.json` (generated by `scripts/gen-composer-eol-map.js` from the monorepo's `replace: self.version` table — the last non-empty `replace` per relevant major, unioned; NOT the union over all versions, which drags in `symfony/monolog-bundle` and would be a false positive), and `checkEolDeps` emits **one finding per (framework, manifest, cycle)** carrying `anchor` + `components[]` instead of 50 rows. The **PHP runtime** (`lib/codecs/composer/platform.js`) is evaluated from the Composer platform constraint with a zero-FP rule: a finding only when an exact pin or a bounded constraint (`^7.4` = `<8.0`) proves that even the newest PHP allowed is EOL; an open constraint (`>=7.2.5`) yields a chapter-0 `php-runtime-undetermined` note, never a verdict. The PHP runtime is a **finding, never a dependency** — it does not enter `resolved` (no CVE/OSV/SBOM/purl). The **outdated** check reports direct deps only, and the Maven pass skips transitives at **fetch** time (`checkOutdatedDeps` filters `scope==="transitive"` before querying — on a real reactor transitives outnumber directs 5-10×, so querying-then-discarding them was the pass's main wall-clock cost).
6. Produces a self-contained HTML report + Word-compatible `.doc`, organised by ecosystem and by defining manifest, with a Priority column, a Licenses chapter, per-tool fix recipes and a structured **executive summary** (`renderExecutiveSummary` in `lib/cve-report.js`): three blocks — (1) the **top-3 most critical** ranked by composite priority, scoped to **direct production deps** with worst-transitive fallback (tagged `transitive`, picked by `pickTopCriticalMatches`), **each row listing ALL of that finding's CWEs** right beside it (not a separate report-wide CWE aggregate — that whole-report CWE distribution is a chart, not exec text); (2) the **2 most-overdue EOL** frameworks (`pickTopEol`); (3) a one-line *"everything else"* (high/critical counts, dev CVE, vendored-JS, EOL/obsolete/outdated, **unmanaged native binaries** count, scan alerts). A "📋 Copy summary" button emits a Word-pasteable rich+plain mirror of all three. Also exports machine-readable **CycloneDX 1.6 SBOM** (vulnerabilities inline, `--report-sbom`), **CSAF 2.0 VEX** (`--report-csaf`), a flat **findings JSON** (`--report-json`) and a **SARIF 2.1.0** log for GitHub/GitLab code scanning (`--report-sarif`), plus an Excel `.xlsx` workbook (`--report-xlsx`).
7. CI-friendly: `--fail-on <low|medium|high|critical|kev>` sets a non-zero exit code (KEV = fail only on known-exploited). Triage with `--ignore <file>` (CVE/coord/glob rules) and `--vex <file>` (ingest a CSAF VEX) suppresses accepted-risk / false-positive findings from the report + gate while keeping them flagged in the exports.

No build tool (`mvn`, `npm install`, `yarn`) is required on PATH — `pom.xml` / `package-lock.json` / `yarn.lock` are parsed directly.

## Running

```bash
npm install
npm test                  # ~1270 unit tests via node --test

# basic cleanup workflow
node fad-checker.js -s ./proj                                        # read-only, full report
node fad-checker.js -s ./proj -t ../pom-clean -e "^client\\."        # extract only: write cleaned tree, no scan
node fad-checker.js -s ./proj -t ../pom-clean -e "^client\\." --snyk # also drive snyk

# read the full usage doc
cat docs/USAGE.md
```

Binary builds (requires `bun`):

```bash
npm run build:linux   # → dist/fad-checker
npm run build:win     # → dist/fad-checker.exe
npm run build         # both
```

Guardrails enforced at startup:
- **Releasing = pushing a version bump, nothing else.** `.github/workflows/release.yml` runs on every push to `main`, reads `package.json`, and publishes **only if no GitHub release `v<version>` exists yet** — it creates the tag itself (and moves a stray pre-existing tag onto the released commit), builds the binaries and publishes the release with the `[Unreleased]` CHANGELOG section as notes. **Don't `git tag` by hand** — it is pointless (the workflow does it) and, before 2026-09-14, a manual tag made the guard skip the release entirely (v2.4.8); the guard now keys on the release, so a stray tag is repaired rather than fatal.
- `--target` is required only when you want a cleaned POM tree — and `-t` is an **extraction step, not a scan**: after the cleaned tree + Maven POM analysis (missing parents, excluded libs, and the online *existence* check for private-lib classification — the only network call, skipped under `--offline` or when `reachableRepos()` finds no repo answering a 5 s HEAD preflight) the run **returns** (`extractOnly` in `fad-checker.js`). The scan + report join only when something consumes them: `--snyk`, any `--report-<type>`, `--fail-on`/`--fail-on-new`, `--baseline` (`scanRequested`). Locked by `test/extract-mode.test.js`. Without `-t` the run is read-only and produces the full report.
- `--target` may not equal or be a subdirectory of `--src`.
- `--target` is `rimraf`'d before being rewritten — never point at anything precious.

Only package names are sent.
lib/merge-sources.js         mergeBySource — the seam where every source meets every other. ALIAS-AWARE: the same advisory can be keyed by its CVE (OSV) or its GHSA remoteId (Packagist records with no cve field), and aliases/ghsa resolve the collision instead of duplicating.
lib/osv-db.js                Offline-COMPLETE OSV matching from an imported local OSV DB (Maven `all.zip` → compact index). `--osv-db`. Fills offline Maven recall when the per-dep OSV cache is cold (different machine / TTL-expired / offline-discovered deps); reuses osv.js#vulnToMatch + maven-version range eval. Additive (merges via mergeBySource, online +0).
lib/malware.js               Supply-chain risk lane (pure, offline). `flagMalicious()` elevates OSV `MAL-…`/malicious advisories already in the match set (gate hard-fails on them, any `--fail-on` level); `detectTyposquats()` flags npm/PyPI names one Damerau edit from a popular package (`data/popular-packages.json`), opt-in `--typosquat`. JSON export carries `malicious` flag + `typosquat[]` + summary counts.
lib/nvd.js                   NIST NVD enrichment (CVSS, references, CPE configurations, CWE list). WITHOUT an NVD key the fkie mirror goes FIRST (all CVEs in parallel, no rate limit) and only what it lacks (404 = not mirrored yet, or mirror failure) goes to NVD, paced, with the guard's full retry schedule — NVD must answer or the run stops. WITH a key: NVD first; on NO answer (403/429/5xx/transport — a 404 is an answer) falls back to the fkie-cad/nvd-json-data-feeds git mirror (`providers/nvd.js` op `cve-mirror`, same `cve` JSON, bucket = id minus last 2 digits + `xx`), then to a stale cached record, and only then reports the hole via `noteFanoutExhausted` (run aborts). With the mirror on, the NVD request carries its own AbortSignal so the guard skips its retry schedule (one request, not 40 s of backoff); `--no-nvd-mirror` restores NVD-only + retries. ## Important conventions

- **`coord()` always trims**: real-world POMs occasionally contain whitespace around `<artifactId>`. Every coord-derived lookup goes through `coord()` in `lib/core.js`.
- **Coordinates are `${…}`-interpolated, not just versions**: a declared dep's `groupId`/`artifactId` can be a Maven expression too — reactor sibling deps routinely use `${project.groupId}`/`${project.artifactId}` (built-ins, present in each pom's `props` via `core.js` `localVars`). `collectResolvedDeps` (and `lib/maven-reactor.js`) run `resolveDepVersion()` over **g/a/v**, so coords resolve to `com.acme:sibling`, never a literal `${project.groupId}:…`. (Raw `${…}` is kept in the rewritten cleaned POM on purpose — Snyk's own `mvn` resolves it.)
- **`byId` keys are never polluted with `undefined`**: only indexed when both `groupId` and `artifactId` are present. Enforced by test.
- **All profiles are merged, never prompted for**: every profile's deps are unioned so Snyk sees every dep any profile could pull in. `activeByDefault` wins only for property value conflicts.
- **No `process.exit(1)` mid-pipeline**: a parse/rewrite failure for one POM logs and continues so the summary still prints.
- **HTML report is self-contained**: inline CSS, no external assets. The `.doc` variant is the same HTML with Office XML namespace meta tags — Word opens it natively.
- **A table must never widen the PAGE**: a table's minimum width is the sum of its columns' longest UNBREAKABLE token, and chapter 1 nests ecosystem → manifest → scope, each level costing ~30px (`details.report-subsection > div`). Measured at 495px of horizontal document overflow on the Dubbo report before the fix. Three rules keep it at 0 (verified 768→1600px): `overflow-wrap: anywhere` on the columns that hold long tokens ONLY — it is what shrinks min-content width, unlike `word-break: break-word` — with short cells (`td.cve`, `td.fix`, the severity badge) explicitly exempt so an identifier is not chopped into `CVE-`/`2021-`/`44228`; `.table-wrap { overflow-x: auto }` so any residue scrolls the table, never `<body>`; and a flattened inset past the second nesting level. The `.doc` stylesheet already hard-fitted tables for Word; the HTML never did.
- **Report i18n (`--lang en|fr`, `lib/i18n.js`)**: the **English string is the KEY** (`t("Copy table")`), so an `en` report is byte-identical to the one that existed before i18n — which is what keeps a suite asserting exact strings meaningful — and a missing translation degrades to English instead of rendering a raw key at a client. **Scope is the report's own chrome.** Text from a data source (CVE descriptions, advisory summaries, registry deprecation reasons, endoflife notes) is NEVER translated: it is evidence, and paraphrasing evidence in an audit is wrong. **CWE titles are the one exception** (`data/cwe-names-fr.json`, 189/189): MITRE publishes CWE in English only, so those are fad's own translations and MITRE's original travels with every one of them — tooltip in HTML, parentheses in the `.doc`, where tooltips do not exist. **Coverage is the WHOLE report**, not the headings: chapter titles and their counts, every table header and cell affix, the scope chips, the "defined in / version managed by / pulled in via" footers, the CVE detail panel's labels and reference categories, every chapter's intro paragraph, every status pill (`pristine`, `should-be-managed`, `nom≠empreinte`, `🔑 CLÉ PRIVÉE`, …), the scan-warning headings, the licence categories, the eight methodology limitations, the per-ecosystem fix recipes (`lib/codecs/recipes.js` — its `pinIntro(cnt, t)` takes the translator; `noFix`/`pinSection`/`directSection` are keys the renderer translates) and the empty states. Three files hold every key — `cve-report.js`, `charts.js`, `recipes.js` — and `test/i18n.test.js` asserts the catalogue and those three agree **in both directions**: zero unreachable entries, zero reachable keys without a French wording. **A CVSS severity stays in NVD's vocabulary** wherever it is the VALUE of a finding — the badge, the priority band, the diff's per-severity breakdown — because that is the data source's own wording (and `severityOf()` in the clipboard script reads the badge text to filter "criticals only"); the labels around it are translated. A catalogue value may be a **`[singular, plural]` pair** picked by `vars.n`: English leaves "1 obsolete" alone, French does not, and the English side is untouched because `CATALOG.en` is empty. Anything that also travels in a machine-readable export is data, not chrome — `excludedDirs[].reason` and the provenance manifest are built in English once, and the one prose field the report displays (`{n} entries`, `catalog {v}`) is localised at RENDER time by `provenanceDetail()`, so `--lang` can never change an export's bytes. `charts.js` takes the translator through `opts.t` and a CWE-title resolver through `opts.cweName`, so it keeps no i18n dependency of its own; its default translator still INTERPOLATES `{n}` (an identity function would ship a literal `{n}` to every caller that passes none). The **copied executive summary** is built as SENTENCES in JS, so it carries its own translations with `{placeholder}` interpolation rather than concatenation — word order differs between languages, and `Top {n} …` must be able to become `Les {n} …`. The rich (Word) flavour translates the sentence with marker characters and substitutes the bolded values into them, so the bolding survives a reordering. The **clipboard script is a module constant** and cannot call `t()` — it builds its menu labels and flash messages in the browser — so `browserI18nScript()` ships those few strings as page data (`window.__FAD_T`) and the script falls back to English for anything absent; in English the table is empty and therefore not emitted at all. **Table column widths key on `data-tbl`, not header text** (`TABLE_COLGROUPS`): they matched the English `<thead>` until French dropped the `<colgroup>` on seven of eight tables and Word laid them out on content width. A layout contract anchored to a human-readable label breaks the first time someone edits the label.
- **Report wording is per-ecosystem, never Maven-by-default**: "Declared in (1 POM)" counted every descriptor as a pom.xml, and "Add &lt;exclusion&gt; in root POM" was the no-fix advice given to npm, PyPI, Go and the rest. `descriptorCount()` names the file kind when the paths share one (`3 pom.xml`, `2 package.json`) and falls back to `N descriptors` when they do not; each recipe in `lib/codecs/recipes.js` now carries a `noFix` line and `renderActionCell` reads it. Genuinely Maven-only wording (the `parent POM` chip, `versionSource.via === "parent"`, the Maven recipe's own "paste into the root POM") stays — those concepts only exist for Maven deps.
- **The pinned chapter bar is one row of dropdowns** (`renderToc`): sub-chapters used to sit inline behind a `›`, so a full report listed sixteen links and the sticky bar wrapped onto two rows — a third of the viewport, on every scroll. Each chapter with sub-chapters now reveals them on hover or keyboard focus. Deliberately **CSS-only** (`:hover` / `:focus-within`): a nav that needs JavaScript to open is a nav that silently stops working in a report opened from a mail attachment. The invisible `::after` strip under each chapter bridges the gap to its menu, or the pointer crossing it would close the menu. Root 3 is **Maintenance / EOL**, named for the part a reader scans the chapter list for. The bar is divided into **equal cells** (`flex: 1 1 0`), one per chapter, each centred in its own and separated by a hairline: left-packed natural widths meant a 700-CVE report and an empty one produced two completely different bars, so the eye had to re-find every chapter. A menu opens centred under its cell, except the last one, which is right-aligned or it would hang off the edge.
- **A finding's "defined in" names MODULES, capped at two**: `renderDefinedIn` labels each descriptor with `lib/module-names.js` and shows at most 2 (`+N more`), the full path staying as the tooltip. "dubbo-dependencies-zookeeper" instead of "dubbo-dependencies/dubbo-dependencies-zookeeper/pom.xml" says the same thing in a quarter of the width, and that cell's width was what squeezed the Description column. `RENDER_CTX.moduleNames` is populated at the TOP of `buildBody`, before any table renders.
- **The injected `<colgroup>` is a HINT in HTML, a clamp in Word**: `injectColgroups` now runs for both outputs, but the HTML deliberately does NOT set `table-layout: fixed`. It was tried: with `overflow-wrap: anywhere` a cell has no natural minimum, so an 8% column laminated `org.apache.logging.log4j:log4j-core` into four characters per line. Auto layout takes the same proportions as a hint and refuses to go below what content needs; `td.dep` also carries an explicit `min-width` floor for the same reason. Word gets `table-layout: fixed` in its own stylesheet, where it has no better option.
- **A separator that only exists in CSS does not survive a copy**: the merged priority cell spaced its badge from its score with a `margin` and drew the `EPSS:` / `Published:` colons with a `::after`. Both render correctly on screen and are absent from `textContent`, which is what the clipboard's plain-text flavour and `tableToTsv` read — a Word paste came out as `CRITICAL9.8` and `EPSS100%`. Separators now live in the markup; the margins stay only for rhythm.
- **Priority / severity / published are ONE cell, four lines** (`priorityCell`): band + KEV, severity + CVSS score, then `EPSS:` and `Published:` as labelled dimmed rows (the key is an inline-block with a min-width AND a right padding — the padding applies after the `::after` colon, which min-width alone does not guarantee, so a long key like `Published` stops butting against its value). They are labelled because neither a bare percentage nor a bare date has a column header any more. Three narrow fixed-width columns were spending ~22% of the table on ~8% of the information. **Both Word paths must be kept in sync when this cell changes**: the `.doc` stylesheet states `display` explicitly (Word honours block/inline on a `<div>` unreliably) and `inlineStylesForWord` rewrites the inline chips to `<span>` with inline styles, because the clipboard carries no stylesheet. `TABLE_COLGROUPS.cve.match` keys on the exact header text — editing the header without it silently drops the Word column widths.
- **Codec abstraction**: every ecosystem lives behind a codec (`lib/codecs/*`) implementing one interface (`detect`/`collect`/`coordKey`/`formatCoord`/`osvPackageName`/`checkRegistry`/`resolveEolProduct`/`recipe`/`nativeScanners`). The orchestrator loops over the codecs `detectCodecs()` returns. OSV/NVD/CPE and the endoflife.date fetch are **shared, ecosystem-agnostic** services that ask the codec for a package/product name. CVE-index (maven) and retire.js (npm) are `nativeScanners` owned by their codec. Adding an ecosystem = adding a codec, no orchestrator edits.
- **Map keys are ecosystem-namespaced** (`dep.coordKey`): Maven uses a **bare** `g:a` (kept prefix-free so `transitive.js` internals and existing tests are untouched); npm uses `npm:name`; new ecosystems use `nuget:`/`composer:vendor/pkg`/`pypi:`. Bare `g:a` is collision-free against those prefixes. Built by `makeDepRecord()`; `groupId`/`artifactId`/`pomPaths` are kept as real duplicated alias fields (not getters — depRecords are spread in hot paths).
- **Every distinct version is scanned, not just the highest**: when profiles/modules pin the same `g:a` to different versions, the resolved-dep entry keeps `version` = highest (representative for display/EOL/outdated) but `versions` = all distinct concrete versions. CVE matching (`matchOne`) and OSV (`queryOsvForDeps`) iterate `versions` so a vuln affecting only a lower-versioned profile variant isn't missed. Match dedup keys are `g:a:version|cve.id` (version included) to preserve per-version findings. Each transitive version carries a `maskedVersions[]` provenance entry (`{version, via, viaPaths, module, depth, scope}`) written by `lib/maven-reactor.js`, one per module that resolves it.
- **Maven is resolved module by module (`lib/maven-reactor.js`)** — Maven never resolves "the reactor"; it resolves each module with ITS effective model. fad used to resolve one merged tree for the whole scan root (one global `rootDepMgmt` = the highest version of every coord, every external parent's managed table first-wins, every pom's property overrides applied everywhere) and patch it with an additive per-module overlay — on a scan root holding several projects that re-versioned one project's transitives with another's pins (FPs on versions no classpath holds) and hid real versions (FNs). `resolveReactor` resolves every pom in `propsByPom` on its own: `moduleManagement` (precedence: local chain explicit entries closest-first — local import BOMs are expanded inline by `core.getAllInheritedProps` and count here — then the external parent chain's explicit entries, then EXTERNAL import BOMs declared in the chain first-declared-wins, then what the external parent itself imported; property overrides = THIS chain's `<properties>` only), `moduleDirects` (own `<dependencies>` + those inherited from the local parent chain, child-first closest-wins — **don't "simplify" that back to the module's own `<dependencies>`**, it hides a parent-declared remediation and the old overlay then fabricated CVEs against the overridden version, locked by `test/version-overlay-inherited-direct.test.js` — + the EXTERNAL parent's own `<dependencies>`; version from the declaration else the managed one, scope from the declaration else the managed scope, exclusions declared ∪ managed, a version range resolved to the highest published version inside it, `<optional>` directs included since optional only affects consumers, `system`/`import` skipped, `-e` honoured), then `resolveTransitiveDeps` against that module's pins only. The maven-codec records are REBUILT from the union: `versions[]`, `versionPaths` (version → declaring pom), `versionScopes`, `maskedVersions[]` (version → resolving module + chain + scope); `manifestPaths` = declaring poms only (a pom that merely manages a version is not where the dep is defined); a coord no module holds is deleted (a `<dependencyManagement>`-only entry, an import BOM). Records keep their identity (same object, same `manifestPaths` array). Gradle (`ecosystemType:"gradle"`), embedded and binary records are not touched — `expandWithTransitives` still serves them (with `only:` restricting it to Gradle when the reactor ran) and serves `--import-anonymized` (no source tree). Runs with `--no-transitive` too (directs and their managed versions are still per module). Offline-aware, `effCache`-memoised. Locked by `test/maven-reactor.test.js` (every shape checked against `mvn dependency:tree`) and the ported `test/version-overlay*.test.js`. Measured on the public **Apache Dubbo 2.7.8** benchmark: OSV-Scanner recall 705/705 online and air-gapped; vs the global pass it removed 71+9 pairs (each confirmed absent or fixed by `mvn dependency:tree`) and added 31 real ones (netty 4.1.35 in dubbo-rpc-grpc, netty-all 4.1.25 in dubbo-rpc-rest… masked before) — see [`docs/BENCHMARK.md`](docs/BENCHMARK.md).
- **A `<dependencyManagement>` entry is a PIN, not a dependency**: `collectResolvedDeps` still collects it (it versions versionless declared deps), flagging a coord seen ONLY there (scope≠import) `managedOnly`. For Maven the reactor decides — a coord no module holds is deleted. For Gradle (constraints / forces are `managedOnly` records with `pinMinimum` for a constraint) `expandWithTransitives` never seeds them, promotes one the graph reaches (`promoteManagedToTransitive`, `managedIn` = the pinning file) and `settleManagedOnly` drops the rest. Measured: a module pinning `jackson-mapper-asl:1.9.13` it never used was reported as a direct dep with a CRITICAL. Locked by `test/managed-only.test.js`. `expandWithTransitives` also seeds/pins **Maven-ecosystem records only** (an npm Map entry used to become an `undefined:<name>` Maven Central lookup) and never seeds `gradle.lockfile` entries (the lockfile IS the resolved graph).
- **Mediation follows `mvn dependency:tree`, not a simplification of it** (`lib/transitive.js`): `resolveTransitiveDeps` walks LEVEL BY LEVEL (POMs of a level fetched in parallel, applied in declaration order) — nearest wins, then first declared, deterministically (the old worker pool claimed a coord when its POM *arrived*: the version depended on network latency); the winner keeps its version and a later wider-scope path only widens the scope, re-propagated to its subtree (Maven's JavaScopeSelector); a `rootDepMgmt` entry is `{version, exclusions, minimum?}` or a bare version string (`minimum` = a Gradle constraint: a floor, not a force); managed `<exclusions>` apply to the subtree; a dep with no `<scope>` (`scopeDeclared:false`) takes its POM's managed scope and, without its own exclusions, the managed ones (dependencyManagement injection); a version RANGE resolves to the highest published version inside it (`fetchMetadataVersions`, maven-metadata.xml, cached 24 h, any age offline). `effectivePom`: a child redeclaring an inherited parent dependency overrides it; depMgmt precedence = explicit (own or inherited-explicit) > own imports first-declared-wins > what an ancestor imported (`fromImport` marks); `${project.parent.version}`/`groupId`/`artifactId` are builtins. Profiles (`core.js`): the `activeByDefault` profile's `<properties>` override the main ones. Locked by `test/maven-reactor.test.js` + `test/maven-mediation-fidelity.test.js`.
- **Version ordering IS Maven's `ComparableVersion`** (`lib/maven-version.js`): unknown qualifiers sort AFTER the release, lexically among themselves (`32.0.0-jre > 32.0.0`, Jetty `9.4.11.v20180605 > 9.4.11`), a number beats any qualifier unless it is a trailing zero (normalised away), `1.0.1 > 1.0-1` (`-` opens a sub-list), `1-rc < 1-rc1`, digit→letter is a separator (`1.0a1` = alpha-1). The old ranking put unknown qualifiers just below the release, so guava `32.0.0-jre` was "affected" by the CVEs it fixes and Jetty's fixing release by its own CVEs. Locked by `test/maven-version-oracle.test.js` against `test/fixtures/maven-version-oracle.tsv` — 1 542 pairs whose sign was produced by maven-artifact 3.9.16 itself (0 mismatch on 9 816 real-version pairs at the time of the fix). Ranges: `isVersionRange`/`parseVersionRange`/`resolveVersionRange` — a range is never compared as a version.
- **A depRecord is COORD-WIDE; a match carries ONE version — attribute it** (`lib/attribution.js#attributeMatchOrigins`, called from `fad-checker.js` after ALL match sources merge and before anything reads scope/paths). The collectors merge every occurrence of a `g:a` across the whole scan root into ONE record, so `versions[]` and `manifestPaths[]` are both coord-wide sets **with no link between them** and `scope` is a single merged value; `matchOne` then clones the dep per version (`{...dep, version: ver}`), and the clone inherits that coord-wide list. Harmless on a single reactor, **wrong on the shape fad is actually pointed at: an audit root holding SEVERAL INDEPENDENT projects** (each pom its own external parent, no shared reactor) — see [[multi-project-scan-root]]. Two symptoms, one root cause: (1) project A pins `jackson-databind:2.15.3`, B pins `2.17.0` → both projects reported as holding BOTH versions, each version's CVEs landing on both; (2) A declares `commons-compress:1.27.1`, B pulls `poi-ooxml → 1.24.0` and the per-module resolution legitimately adds it → the finding (REAL for B) renders as a **direct dep of A's pom**, the very pom that pins the fix, topping the exec summary's "direct production dependencies". The pass consumes two provenance sources per match: **`versionPaths{}`** (`lib/dep-record.js`, version → declaring manifest(s), maintained on merge by the collectors) → narrow `manifestPaths`; **`maskedVersions[]`** (`lib/maven-reactor.js`, one entry per resolving module) → re-stamp `scope:"transitive"` + `via`/`viaPaths`/`depth` + the resolving module. A version with neither (global-pass transitive) is left alone. Always **clone, never mutate** the shared record (other matches hold it), and keep `pomPaths` the SAME array object as `manifestPaths`. Locked by `test/attribution.test.js`.
- **A cache filename is ONE path segment, always**: `lib/osv.js#cacheKey`, `lib/transitive.js#cachePath`, `lib/maven-license.js`. Coordinate and version both come from a scanned repository, so neither may introduce a separator. This is not theoretical: a package-lock v1 entry for a URL-installed dep records `"version": "https://registry.npmjs.org/x/-/x-0.12.5.tgz"`, which turned the OSV cache path into a nested directory and killed the scan on `ENOENT` mid-step. Everything outside `[A-Za-z0-9._+-]` collapses to `%` — a set chosen to leave every well-formed Maven/npm coordinate byte-identical, so warm caches written before the fix are still found.
- **A URL is not a version** (`lib/codecs/npm/parse.js#normaliseNpmVersion`, applied at the single point npm records are built, `npm/collect.js`): a **registry tarball** URL carries the real semver in its filename, so it is recovered and the package becomes scannable (`javascript.util` went from crashing the run to `0.12.5`, outdated → `0.12.12`). Anything else — git ref, `github:` shorthand, `file:`/`link:`, a nightly with no version in its name — has NO concrete version and resolves to `null`, so the existing rule applies: only concrete versions are matched, an unresolved dep is reported as unresolved rather than assumed vulnerable to every CVE its coordinate ever had.
- **npm no-lockfile = best-effort (not skipped)**: `package.json` without a sibling `package-lock.json`/`yarn.lock` is parsed best-effort — pinned exact versions (`"1.2.3"`) are scanned, ranges (`"^1.0.0"`) are skipped, and a `no-lockfile` warning (chapter 0) flags the partial coverage. (Earlier versions skipped such manifests entirely.)
- **EOL rows expand to exact descriptor references** (`renderEolDetail` in `lib/cve-report.js` + `lib/descriptor-refs.js#findDeclarations`): each EOL row is a `cve-row`/`detail-row` pair (same toggle JS, same Word force-open) whose panel gives, per component, `file:line` + the declaration text. The line finder is **strict per descriptor kind** (pom block with matching groupId AND artifactId, lockfile entry header, requirements line starting with the PEP 503 name, …) and returns NO line rather than the first mention — a wrong line is worse than none. Grouped findings' `components[]` carry their own `manifestPaths` (or `scope:"transitive"` + `via`) from `eolComponent()` in `lib/outdated.js`; a transitive component must never be filed under the anchor's pom.
- **A dark source aborts the run (online only)**: `lib/source-health.js`. Every public data client calls `getResource`; `fad-checker.js` configures its route before the first request and retains the source-health guard for direct fetches. A lookup served from the warm cache issues NO request, so a source whose cache covers everything stays silent even if the site is down — that is the "100% from cache, no alert" rule, and it falls out of the design rather than needing counters. A request that gets no usable answer is retried **`--retries` times (default 5) waiting 5+n seconds** (6, 7, 8, 9, 10; `setRetryAttempts()` run-wide, `guardedFetch({retries})` per guard, `0` = no retry), each retry logged via `ui.interject` (spinner-safe, survives in a CI log); the schedule is **shared per source**, so 400 concurrent lookups against one dead host run ONE schedule, not 400. **The schedule applies only to single-endpoint sources** (EPSS, KEV, NVD, OSV, endoflife.date, deps.dev/CIRCL). A request carrying an `AbortSignal` is passed straight through: its caller owns the deadline AND a failover across mirrors/bases (`lib/maven-repo.js#tryRepos`, `lib/registries.js#fetchFirstOk`, the npm registry), so retrying inside that budget is futile once the signal has fired and costs **40s of backoff per dead mirror** where the rotation would have moved on instantly — measured, and the reason the outdated pass regressed. Those rotations report their own exhaustion instead: `noteFanoutExhausted(url, reasons)` marks the outage only when **no** host answered, since a 404 from every base is an ANSWER (it is how an internal package is detected), not an outage. Exhausted → the run stops at the next step boundary (`ui.Progress`'s `onStepEnd` hook) **before anything is written**, printing the domain, the error codes, the first failing URL and the flag that disables that source, and exits **2** — distinct from the `1` that `--fail-on` uses, so CI can tell "vulnerable" from "not trustworthy". A definitive **404/410 is an answer, not an outage**: it is how private/internal packages are detected, and treating it as a failure would abort every normal monorepo scan. `--offline` never aborts (that mode's contract is already "warm cache only").
- **Help / version flags**: `-h, --help` and `-v, --version`. `--verbose` is **long-form only** — `-v` used to mean verbose and now means version, so an old `fad-checker -s . -v` prints the version and exits 0 instead of scanning. `-V` is kept as an alias for `--version` (it was the version flag before) by rewriting it in `process.argv` before parse, since commander allows a single short flag per option. A bare invocation (or a lone `--verbose`, which cannot be a verbose scan) prints a mini help carrying the running version and exits **non-zero** — nothing was scanned, so it must not read as a clean run.
- **`--help` is one screen; the long tail folds into -d / -a / -r** (`lib/cli-groups.js`). It had reached 176 lines and eighty options, thirty-six of them a `--no-<x>` or an opt-in switch — which are two lists, not thirty-six decisions. `-d eol,nvd` turns things off, `-a licenses,snyk` turns on what is off by default, `-r html,json` picks the outputs, `-o` is the output directory. The folded flags **still work**: they are `opt.hidden = true`, not removed, because deleting them would break every script in the wild to achieve the same readable help. Cache / registry / config commands are hidden the same way — they manage the tool, not a scan. `--help-all` prints everything. An unknown token is a **hard error (exit 2)**, never ignored: a silently dropped `-d nvd` would yield a report claiming coverage the run did not have. `osv-db` is deliberately in BOTH lists — it is tri-state (auto), so it can be forced on or off.
- **`--ecosystem` is a list**: `auto` (default = `detectCodecs()`) | `all` | comma list `maven,gradle,npm,nuget,composer,pypi` (legacy `both`/`maven`/`npm` still parse). Per-codec opt-out via `--no-maven`/`--no-gradle`/`--no-npm`/`--no-yarn`/`--no-nuget`/`--no-composer`/`--no-pypi`/`--no-go`/`--no-ruby`; `--no-js` is an alias for `--no-npm`+`--no-yarn`. `--no-jars` disables the Maven codec's embedded-binary scan; `--no-binaries` disables the native-binary (binary codec) scan; `--no-certs` disables the certificate / key-material scan (`--cert-expiry-days <n>` sets the expiring-soon window, default 90). `--eol-support` adds the `unsupported` EOL band (off by default); `--no-eol` skips the endoflife.date check entirely. The binary codec is a cross-cutting catch-all: in `auto` mode it's always a candidate (committed native libs can live in any project, and `detectCodecs`' manifest-glob matcher misses versioned sonames like `libz.so.1`).
- **Unmanaged / native-binary provenance**: `provenance: "binary"` records (committed `.dll`/`.exe`/`.so`/`.dylib`, keyed `binary:<path>`) carry `hashes: {sha1, sha256}` + `declaredName`. They have no resolved coordinate until `lib/hash-id.js` identifies them by checksum (deps.dev → CIRCL), so the Maven CVE-index matcher and the transitive resolver skip `provenance === "binary"`; OSV skips them too (no version). `lib/unmanaged.js#enrichUnmanaged` then sets `identity` + `integrity` (`pristine` = deps.dev exact published-artifact match; `known-good` = CIRCL; `unknown` = neither), and `buildInventory` derives `shouldBeManaged` (identity resolves to a real registry package), `nameMismatch` (filename ≠ checksum identity), `noOnlineInfo`, and `knownMalicious` (free CIRCL signal — there is **no** dedicated malware/AV lane). Surfaced in report **chapter 2.2** and the JSON export's `unmanaged` array + `summary.unmanaged`. Every source is cached + `--offline`-aware (reads warmed cache, never blocks).
- **Embedded-binary provenance**: every depRecord carries `provenance` (`"manifest"` default, `"embedded"` for jar-discovered coords, `"binary"` for committed native libs). Embedded records are keyed `embedded:<manifestPath>` (NOT `g:a`) so they never merge with a declared dep of the same coordinate — that keeps the dedicated **chapter 2.1 (Embedded binaries)** complete and lets a coord that's both declared and embedded show in both places (intended). Match dedup (`cve-match.js`, `mergeBySource`) keys on `dep.coordKey` (identical to `g:a` for declared Maven, distinct for embedded). Embedded coords are excluded from Maven Central transitive resolution (a fat-jar ships its own deps, found by recursion) and counted/gated separately. Exports carry it: SBOM component `fad:provenance`/`fad:location` properties + a unique `bom-ref`, SARIF result `provenance` + the nested-jar `location`, JSON `provenance`.
- **Default outputs are HTML + findings JSON** (was HTML + `.doc`): the JSON is there so the NEXT run has something to `--baseline` against without anyone remembering a flag, and the `.doc` is no longer written for people who never open it (`--report-doc` still produces it).
- **Unified output flags** (`fad-checker.js` → `runReportFlow`): one `--report-<type>` per output (`html`/`doc`/`sbom`/`csaf`/`json`/`sarif`), each with an OPTIONAL path arg (`true` = default name under `--report-output`; string = explicit path; `undefined` = not requested). If NO `--report-*` is given, the default set is HTML + `.doc`; selecting any flag writes exactly that set. `--no-report` writes NOTHING (gate-only) — the scan, terminal summary and `--fail-on` gate still run. The old `--export-sbom/csaf/json/sarif` flags were **removed** (renamed to `--report-*`); `--export-cache`/`--export-anonymized` are unrelated and unchanged. `writeReports({htmlPath, docPath})` writes only the non-null paths (legacy `outputDir` still writes both).
- **CI gating & triage**: `--fail-on <low|medium|high|critical|kev>` (`lib/gate.js`) sets `process.exitCode = 1` after all reports/exports are written, gating on `prodActive` (non-dev, non-cpeFiltered, non-suppressed); `kev` fails only on a CISA-known-exploited finding. `--ignore <file>` (CVE id / coord-glob / `# reason` per line) and `--vex <file>` (CSAF `known_not_affected`/`fixed`, products mapped to coords by purl) mark matches `suppressed` (`lib/suppress.js`) — dropped from the report chapters + gate, retained & flagged in the JSON/SBOM/CSAF/SARIF exports, noted in chapter 0.
- **Differential audits & reproducibility**: `--baseline <file>` diffs the current scan against a prior `findings.json` (`lib/diff.js`) → a `diff` block in the JSON export + a **"Δ Changes since baseline"** report chapter; `--fail-on-new` adds a gate that fails on any *new* production CVE finding (combinable with `--fail-on`). A standalone `fad-checker diff <base.json> <cur.json>` subcommand (intercepted pre-`program.parse`, like `--add-repo`/`--export-cache`) prints the delta and honours `--report-json`/`--fail-on-new`. Every report carries a **provenance manifest** (`lib/provenance.js`, in `projectInfo.provenance` → JSON `provenance` + report chapter 6.3 methodology/limitations) and, unless `--no-checksums`, a **`SHA256SUMS`** integrity manifest written beside the artifacts (`lib/report-integrity.js`).
- **SARIF / JSON exports** (`--report-sarif` / `--report-json`): machine-readable findings. SARIF 2.1.0 carries one rule per CVE with `security-severity` (GitHub Code Scanning) + manifest `locations`; the JSON is fad's own flat all-chapters format for diffing between audits.
- **Source identifiers**: every match carries `source: "fad" | "osv" | "nvd" | "snyk" | "retire"` (or a `+`-joined combination).
- **Anonymized descriptor (offline→online round-trip)**: `--export-anonymized <f>` (offline, needs `-s`) serializes the collected `resolved` Map to a flat `fad-deps/1` JSON keeping only public coordinates (`ecosystem`/`ecosystemType`/`namespace`/`name`/`version`/`versions`/`scope`/`isDev`) — **strips** paths, registry URLs, integrity, parent chains — then exits. **It also carries a `maven` hints block** (`externalParents[]` + `importBoms[]` coords + `propertyOverrides{}`) so a no-source-tree online run can resolve the versionless deps in ONE exchange (see below). `--import-anonymized <f>` (online, **no `-s`**) rebuilds the Map (empty `manifestPaths`, recomputed `coordKey`) via `lib/deps-descriptor.js`, **replays the external-parent / import-BOM backfill from those hints** (the mainline store-based backfill can't run without a source tree), then runs `runReportFlow` purely to **warm the coordinate-keyed caches** — it **writes NO report by default** (it's a cache-warming step, not a reporting one: `options.report` is forced off in the import branch unless an explicit `--report-<type>` is given). Round-trip = export (offline) → import + `--export-cache` (online) → `--import-cache` + normal `--offline -s ./proj` (offline) for the full path-bearing report. **Why the hints matter**: the CVE cache is keyed by `coord+version`; a versionless `spring-boot-starter-actuator` can't warm its cache until something backfills `2.7.18`. Without a source tree online, that needs the external-parent coord — so carrying it (plus the project's version-property overrides) closes the round-trip in one exchange instead of two. Private/public sorting is the auditor's job via `-e` (offline can't check Maven Central); a PRIVATE parent carried in the hints is simply unresolvable online (harmless no-op). If a report IS explicitly requested in import mode it stays path-free (`projectInfo.src` = withheld).

## Gotchas / edge cases worth knowing

- CVE bundle from CVEProject is ~500 MB unpacked. Shells out to `curl + unzip` (fallback to `fetch()` + `unzip` / `Expand-Archive`). Extracted JSON deleted after index build. Ships as `cves.zip.zip` (nested zip) — `extractZip()` recurses up to 3 levels.
- `endoflife.date` API responses cached 7 days; Maven Central version lookups cached 24 hours. Cache lives in `~/.fad-checker/`.
- **Persistent config**: `~/.fad-checker/config.json` (mode 0600). Set NVD key via `fad-checker --set-nvd-key <KEY>` (free, instant from <https://nvd.nist.gov/developers/request-an-api-key> — bumps rate limit from 5/30s to 50/30s).
- **Custom registries (per ecosystem)**: stored under the config key `registries` ({ `<eco>`: [{name,url,auth?,token?}] }) for `maven|npm|pypi|ruby|go|nuget|composer`. **No `maven_repos` back-compat** — that key is gone. CRUD via `--add-repo <eco> <name> <url> [--auth user:pass] [--token TOK]`, `--remove-repo <eco> <name>`, `--list-repos` (grouped); one-off `--repo <eco>=<url>` (repeatable). Each codec's `fetch*` (npm/pypi/ruby/go/nuget/composer `registry.js`) takes `opts.registries`, tries them first (per-registry auth), public base appended **last** by `registries.withPublic` — byte-identical to the old single-base behaviour when empty. PyPI/Ruby custom bases must speak the same JSON API (not a bare PEP 503 simple index); **NuGet** bases speak the v3 registration API (a service-index `…/index.json` is auto-resolved to its `RegistrationsBaseUrl`, memoised); **Composer** custom bases are queried via the v2 `<base>/p2/<vendor>/<pkg>.json` metadata API (converted to the packagist `package` shape by `composerV2ToPackageObject`).
- **Walk pruning (`lib/path-filter.js`)**: every directory walker (Maven `core.js`, `detectCodecs`, npm `parse.js`, composer/go/nuget/pypi/ruby codecs, `maven/jar-scan.js`, `binary/scan.js`) takes a `skipDir(absChild, name)` predicate built by `makeDirFilter`. It combines the walker's own basename `SKIP` set (the **default excludes**, bypassable with `--no-default-excludes` / `defaultExcludes:false`) with user `--exclude-path` globs (gitignore-style via `minimatch`, matched against the path **relative to `srcRoot`**; a glob prunes the dir AND its subtree). `excludePath` is **unioned** across config layers (CLI + file + env + global), like registries. `parallel-walk.js#walkDirs` now passes the child's absolute path to `skipDir`. Each `codec.collect(dir, opts)` receives `opts.excludePath` + `opts.defaultExcludes` and builds the filter (`srcRoot = opts.srcRoot || dir`). **retire.js** is the exception — it does its own internal walk, not `makeDirFilter`, so it gets the same policy translated to a retire `--ignorefile` by `lib/retire.js#buildRetireIgnorePatterns` (same `excludePath`/`defaultExcludes` threaded through the npm codec's retire `nativeScanner`).
- **Layered options (`lib/options-env.js`)**: precedence **CLI flag > config file (`--config <file.json>` / `./.fad-env.json`, JSON keyed by camelCase option names) > `FAD_CHECKER_ENV` (a CLI-flag string, parsed via a throwaway commander clone) > `~/.fad-checker/config.json` > commander defaults**. A file/env value fills an option only when `program.getOptionValueSource(name)` is `default`/undefined (user didn't pass it). `registries` are **unioned** across layers, never overridden. Source flag has aliases: `-s`/`--src`/`--source` + JSON `source`/`src` → internal `src` (no code-wide rename). Wired in `fad-checker.js` right after `program.parse()`; `regMap`/`registriesFor(eco)` threaded into `runReportFlow`.
- **`--offline` umbrella flag**: skips every network call (CVE/OSV/NVD/EPSS/KEV/Maven Central/endoflife/npm-registry/retire). Falls back to whatever is already cached. Per-source variants (`--cve-offline`, `--no-osv`, `--no-nvd`, `--no-epss`, `--no-kev`, `--no-retire`, `--no-transitive`) and per-codec toggles (`--no-maven`/`--no-npm`/`--no-yarn`/`--no-nuget`/`--no-composer`/`--no-pypi`, `--no-js`) still work independently. npm registry deprecation always runs when online; npm (and Maven) outdated is gated by `--no-all-libs`. **License detection is opt-in (`--licenses`, off by default)**; when enabled it piggybacks on the registry passes (no extra fetch) + Maven cached POMs. (Legacy `--no-licenses` is accepted as a no-op since licenses are already off by default.) **Zero-data-sent guarantee**: `--offline` makes literally zero network calls (reads only `~/.fad-checker/` caches, transmits nothing) — locked by `test/offline-guarantee.test.js` (tripwire fetcher that throws if touched, on a cold cache) and auditor-reproducible via `unshare -rn … --offline` (no-network namespace → byte-identical findings). This is a headline air-gapped selling point: fad resolves the **Maven transitive graph offline**, which OSV-Scanner/Trivy/Dependency-Check cannot (they disable transitive resolution or require a network DB) — measured 181/202 vs OSV-Scanner's 64/202 air-gapped on a 25-module project.
- **Machine-readable exports**: `--report-sbom [f]` writes a CycloneDX 1.6 SBOM with vulnerabilities inline (VDR); `--report-csaf [f]` writes a CSAF 2.0 VEX. Both use the full match set (prod+dev+embedded+cpeFiltered; cpeFiltered marked as a property/note rather than dropped). purls are built by `lib/purl.js`.
- `snyk` is not a hard dep — shells out via `execFile`. `snyk` exits 1 on findings; the JSON is still on stdout.
- The cleaned POM is the union of every profile's deps. Counts will be larger than the source POM. Intentional — don't "fix" that.
- Unresolved `${…}` Maven variables stay verbatim in the rewritten POM. `lib/cve-match.js` resolves them lazily via `resolveDepVersion()` when scanning. **External import BOMs** (e.g. `spring-boot-dependencies`, imported in a local `<dependencyManagement>` with `<scope>import</scope>`) **AND external `<parent>` POMs** (e.g. `spring-boot-starter-parent`, whose own parent `spring-boot-dependencies` holds the managed-version table) are resolved by `lib/maven-bom.js`: it collects the BOM coords (`collectImportBoms`) **and the external parent coords** (`collectExternalParents(store)` — core.js only follows LOCAL parents) from the parsed poms, fetches each via `transitive.js#effectivePom` (merges the parent chain, resolves its `${properties}`, recursively expands nested import BOMs → ~1500 managed versions for spring-boot) and **backfills** the version of every declared dep that pins none of its own. Both run in `runReportFlow`'s **mainline** BOM/parent step (not just the `--transitive` overlay, so the warmed cache always captures the parent POMs for offline reuse), BEFORE transitive resolution (so backfilled versions feed it), online or offline (cached POMs, `poms-cache`, never blocks). Import BOMs win over inherited parent versions (Maven precedence). This is why a typical Spring Boot project resolves its `spring-boot-starter-*` instead of dropping them — whether they're pinned by an import BOM **or** inherited from `spring-boot-starter-parent`. **Child property overrides are honored** for the `<parent>` case (Maven semantics): `collectPropertyOverrides(store)` gathers each pom's own `<properties>` and passes them to `effectivePom` as `propertyOverrides`, so a project that redefines `<log4j2.version>2.17.1</log4j2.version>` to patch a CVE resolves `log4j-core` to `2.17.1`, not the framework default — import-BOM-managed versions are NOT overridden (Maven resolves those in the BOM's own context; effectivePom strips overrides at the import boundary). A backfilled dep's resolved version is **nowhere in the source tree**, so it's stamped `versionSource={via:"bom",bom:"<g:a:v>"}` (the top-level `platform(...)`/`<scope>import</scope>` BOM coord the user wrote, e.g. `spring-boot-dependencies:4.0.6` — not the nested `spring-batch-bom` it imports); the report shows it under the dep's `defined in:` footer as `version managed by: <bom> (BOM)` and the findings JSON carries `dep.versionSource`, so e.g. `spring-batch-integration:6.0.3` reads as BOM-managed, not fabricated. Deps that *still* can't be resolved (BOM unreachable, or offline+uncached) surface in chapter 0 as `unresolved-versions` warnings (with the manifest path(s) they're declared in) — and are **excluded from CVE matching**: `matchOne` only compares CONCRETE versions, so an unversioned coord is never assumed-vulnerable to all its CVEs (`cve-match.js`; matches OSV's `!ver` skip). Don't reintroduce a `!ver → status==="affected"` shortcut — it floods the report with bogus CRITICALs shown as version `?`.
- **retire.js** doesn't like `--outputpath /dev/stdout`. We write to a temp file and read it back. Exit code 13 means "vulns found" — expected, not an error.
- **retire.js signatures live in `~/.fad-checker/retire-signatures/jsrepository-v5.json`** (not retire's default `/tmp/.retire-cache`, whose 1 h TTL would force a network refetch). We pass them via `--jsrepo <file>` so retire loads from disk — **no network, no TTL**. `warmRetireSignatures()` fetches them online; `--export-cache` bundles them so phase-3 offline JS scanning works. retire is **offline-only** in the air-gapped flow (it needs the actual `.js` files, absent online) and its findings cache stays path-keyed (`md5(srcDir)`), which is fine since it only runs on the same offline machine/path. With no source dir (`--import-anonymized`), `runRetire` returns `null` (nothing to scan).
